# docs/ 维护规则

本目录存放仓库的维护性工程文档。根 `AGENTS.md` 只保留每个任务都要知道的规则；本文件只规定在这里怎么工作——把一次改动路由到持有其事实的文档，以及让文档集合保持可信的纪律。

## 路由

一次改动使其失效的已记录事实，由该事实的持有文档在同一次改动中更新。此表与实际文档集保持一致（替换示例行）：

| 改动涉及 | 更新 |
| --- | --- |
| （示例）架构、包边界或数据所有权 | `architecture.md` |
| （示例）环境搭建、命令或改动需要哪个检查 | `development.md` |
| （示例）用户可见行为 | `../CHANGELOG.md` |

完整索引与起点见 [README.md](README.md)。

## 维护纪律

- 源码与测试定义实现行为。文字与代码冲突时修文档；绝不记录代码没有实现的行为。
- 一类事实只有一个维护落点；文档之间交叉链接，不重复维护。
- 使文档失效的改动同批更新持有文档；新增维护文档时同批在 `README.md` 加索引行。
- 没把握的事实写 `> TODO:`，不猜测。
- 不为尚不存在的模块或页面预建空壳；内容真实时才建页。
- 不为迁就新代码回写 `.scratch/` 归档；持久结论移入这些文档，且只在确实持久时移。
- 文档按块可读：段落简短、标题稳定、本地引用用相对 Markdown 链接。
